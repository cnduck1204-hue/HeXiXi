# rCore 适配 oscomp 测试套件：改了什么、为什么改

> 目标：让 rCore-Tutorial-v3（RISC-V64 / QEMU）能直接跑 oscomp 评测镜像，
> 按评测机的方式输出 `#### OS COMP TEST GROUP START/END <组名> ####` 并自动关机。
> 原则：先快速适配、不追求完美；能拿分的组优先，做不到的如实记录。

## 一、总体思路

评测机与我们本地环境的三个关键差异：

1. **磁盘**：评测盘是 EXT4（含目录树），rCore 只有 easy-fs（扁平命名空间）；
2. **驱动方式**：评测机先挂载测试盘，然后执行 `*_testcode.sh` 脚本（依赖 busybox / lua 等用户态程序）；
3. **系统调用**：评测用的 busybox / lua / 各 benchmark 都是 musl 静态 ELF，
   需要完整的 Linux 系统调用语义（fork/exec/wait/pipe/mmap/clone/信号…）。

对应的适配分四层做：**文件系统 → 进程/线程/信号 → 系统调用补齐 → 执行链路**。

## 二、文件系统层

| 改动 | 原因 |
|---|---|
| 新增只读 EXT4 驱动 `os/src/fs/ext4.rs`（超级块、块组描述符、inode、extent 树、目录项） | 评测盘是 EXT4，必须能按路径读取 ELF 和脚本 |
| 新增 `fs::resolve_path`（拼进程 cwd） | 脚本里大量相对路径（`cd ./basic && ./run-all.sh`） |
| 进程 PCB 增加 `cwd` 字段，fork 继承 | busybox sh 的 `cd` 必须对后续 open/exec 生效 |
| EXT4 只读 → 加**内存 overlay**（创建/删除/重命名/截断都写在内存） | 写类测试（create/unlink/mkdir/mv）需要写盘能力，来不及实现 EXT4 写 |
| overlay 单文件上限 16 MB | overlay 数据在内核堆里，避免被大文件写爆 |
| `openat` 支持 `O_TRUNC` | fstime 等程序反复覆写同一文件 |
| 目录 fd 表（`dir_paths` / `dir_offsets`） | `getdents64` 要按 fd 列目录、分批返回并在末尾返回 0（busybox readdir 依赖 EOF） |
| 根目录 `/` 用伪文件表示 | stat/open 根目录在 Linux 上合法，rCore 原来没有"根目录"概念 |

## 三、进程 / 线程 / 信号

| 改动 | 原因 |
|---|---|
| `fork` 继承 brk/mmap_top/cwd | 子进程复制父进程地址空间状态 |
| `fork` 后 **`CLONE_CHILD_CLEARTID`** 支持（线程退出时内核清零 `t->tid` 并唤醒） | musl 的 `pthread_join` 依赖内核做这件事——这是 pthread 死锁的根因 |
| `clone(220)` 区分线程/进程（`CLONE_VM` 走线程语义） | musl 的 `pthread_create` 就是 `clone(CLONE_VM|CLONE_THREAD|…)` |
| 线程 trap context：用户 `sp`/`tp` 由调用者给出，内核栈用新线程自己的 | 线程要跑在 musl 给的栈上、用自己的线程指针（TLS） |
| `trap.S` 保存/恢复 `tp(x4)` | rCore 原本刻意跳过 tp（"应用不使用"），导致线程 TLS 永远不对 |
| 系统调用参数从 4 个扩展到 5 个 | `clone` 的 tls/ctid 在 a3/a4，原来的 4 参数取不到 |
| `rt_sigaction` / `rt_sigreturn` / `setitimer` 实现 | UnixBench/cyclictest 用 `alarm()+SIGALRM` 停止计时循环 |
| 自定义 SIGALRM 投递：注入可执行 stub 页（`li a7,139; ecall`）+ 上下文保存页 | 没有用户态 sigreturn 机制，需要内核手工搭帧 |
| `waitpid` 支持 `wait(NULL)` | UnixBench 的 syscall-exec 用例传空指针，原来直接写 0 地址导致 panic |
| `kill(129)` 走 SignalFlags（原有机制） | busybox 后台作业、cyclictest 的 hackbench 回收 |

## 四、系统调用批量补齐

评测用程序（busybox/lua/benchmark）几乎每个都触发几十个系统调用。补齐的关键项：

| 类别 | 系统调用 |
|---|---|
| 文件/IO | `openat` `readv` `writev` `lseek(带 whence)` `fsync` `fdatasync` `ftruncate` `truncate` `getdents64` `newfstatat` `statfs` `fstatfs` `sendfile` |
| 内存 | `brk`（独立堆段 0x2000_0000） `mmap` `munmap`（真正回收帧） |
| 进程 | `clone` `exit_group` `wait4` `set_tid_address` `gettid(178)` |
| 信号/定时 | `setitimer(103)` `clock_getres(114)` `clock_nanosleep(115)` `rt_sigaction(134)` `rt_sigreturn(139)` |
| 调度 | `sched_getparam(121)` `sched_getaffinity(123)` `sched_setscheduler(119)` `sched_yield` `mlock(228)` 系列 |
| 其他 | `fcntl`（`F_DUPFD` 必须返回真实 fd，busybox sh 用它复制脚本 fd） `syslog(116)` `uname` `times` `gettimeofday` `ppoll` `futex` `getuid/getgid` 系列 |

`/proc` 虚拟文件（`meminfo`/`mounts`/`stat`/`uptime` 等）支撑 busybox 的 `free`/`df`/`ps`/`uptime`。

## 五、执行链路（怎么把脚本跑起来）

```
EXT4 盘启动 → 内核识别到 oscomp_runner → 执行它
  → 扫描盘上的 *_testcode.sh
  → 每个脚本 fork + 执行 busybox sh <脚本>
  → 脚本输出 #### START/END #### 标记
  → 全部跑完 init 退出 → 内核调用 SBI 关机
```

关键点：

| 改动 | 原因 |
|---|---|
| 盘上有 `oscomp_runner` 就用它做 initproc | 不依赖具体有哪个脚本 |
| shell 脚本的 **shebang 支持**（`#!`） | 脚本首行是 `#!/bin/bash` 或 `#!/bin/sh`；解释器不存在时回退 busybox sh |
| 内置 mini shell（没有 busybox 时用） | 兜底：无 busybox 的镜像也能解析简单 `for/echo/cd` 脚本 |
| 所有测试镜像里的二进制 chmod +x | busybox sh 检查执行位 |

## 六、内存与启动

| 改动 | 原因 |
|---|---|
| 用户栈 8 KB → **1 MB** | libc-bench 在栈上开 80 KB 局部数组，8 KB 直接溢出 |
| 内核堆 4 MB → **64 MB** | 加载 1.1 MB 静态 busybox / iozone 等大 ELF，以及 fstime 的大缓冲 |
| **从 boot DTB 动态读取物理内存大小** | 评测机 QEMU 内存未知；固定 256 MB 上限会让 libcbench 等内存型测试崩溃 |
| `MEMORY_END` 改为运行时值（DTB memory 末尾 - 1 MB） | 给多少内存用多少 |
| 帧分配器、内核空间映射跟随动态值 | 内核要能直接访问全部物理内存 |

## 七、工具脚本（`tools/oscomp/`）

| 脚本 | 作用 |
|---|---|
| `build_tests.sh` | 编译 26 个 basic 用例（含 `-mcmodel=medany -msmall-data-limit=0 -mno-relax`） |
| `build_busybox.sh` / `build_lua.sh` | 构建 musl 静态非 PIE busybox / lua |
| `make_official_image.sh` | 生成官方布局的 EXT4 测试盘（`basic_testcode.sh` + `basic/` 目录） |
| `build_unixbench.sh` | 构建 UnixBench 各测试程序 + `/bin/true` |
| `build_iozone.sh` | 构建 iozone 并生成测试盘 |
| `build_cyclictest.sh` | 用 numa 桩 + sched wrapper 构建 cyclictest/hackbench |
| `build_lmbench.sh` | 交叉构建 lmbench 依赖的 libtirpc（lmbench_all 尚未完成） |

| 组 | 结果 |
|---|---|

| iperf / netperf | ❌ 依赖网卡，rCore 无网络设备，不可行 |

## 九、已知限制

1. EXT4 只写内存 overlay：断电即失，大文件受 16 MB 上限；
2. 未实现真正的 EXT4 写盘；
3. 信号只处理 SIGALRM（其它信号走 rCore 的 SignalFlags 粗处理）；
4. 调度为单核轮转，CPU 密集型压测（hackbench）非常慢；
5. `tl;dr`：目标是"跑通评测脚本"，不是生产级 Linux 兼容。
